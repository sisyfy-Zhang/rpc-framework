## 声明

- 数字来自固定的一台本机（localhost，AMD Ryzen 5 4600H with Radeon Graphics），只说明这台机器上这个口径下的量级，不可外推到其它机器、其它网络或生产环境。
- 拓扑：client 与 server 是两个独立 JVM，同一台机器（loopback），3 个提供者（[127.0.0.1:21001, 127.0.0.1:21002, 127.0.0.1:21003]），经 zk://127.0.0.1:2181 发现；卡片声明的注册中心：docker-compose/zookeeper（容器未绑核、与压测进程共享宿主核）；三个提供者都经 toxiproxy 原生进程（同 WSL，2.13.0，二进制取自 compose 镜像；只有第 2 个加 toxic）。
- 开环负载（open）：延迟从计划发出时刻算起，发压端自身的调度滞后（见“发出滞后”列）也计入延迟；发出滞后的 p99 明显大于服务时间时，说明压测端本身成了瓶颈，数字不代表被测服务。
- 开环调度线程以忙等对齐节拍，独占一个核；本报告的 CPU 亲和见环境表。
- 第 1 轮发出滞后 p99 超过 1.0ms（dispatcher_delayed）。故障注入 / 阶梯卡上这条规则只记标志、不判无效：这类卡看的是错误数、恢复时间与节点份额，它们不受几毫秒的发出滞后影响；本轮的延迟数字（含 p99）混进了压测端的滞后，仅供参考。
